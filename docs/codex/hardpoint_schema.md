# Hardpoint Schema

Hardpoints are exported in metadata and mirrored by `SOCKET_HP_*` helper sockets in Blender. They describe where equipment may attach; they do not create runtime weapons.

## Fields

- `name`: Stable hardpoint ID without the `SOCKET_` prefix.
- `type`: One of the supported hardpoint types.
- `size`: Integer from `1` to `10`.
- `position`: Blender-space XYZ position.
- `rotation`: Blender-space Euler rotation.
- `allowed_equipment_types`: Equipment categories accepted by this hardpoint.
- `allowed_mount_modes`: Mount modes accepted by this hardpoint.
- `symmetry_group`: Optional group name for mirrored hardpoints.
- `required`: Whether a valid loadout should fill this hardpoint.
- `optional`: Convenience inverse of `required`.
- `visual_socket_name`: `SOCKET_HP_*` marker generated by Blender.
- `gameplay_socket_name`: Legacy or gameplay socket a runtime may use for compatibility.

## Types

- `weapon_fixed`
- `weapon_gimbal`
- `turret`
- `missile_rack`
- `torpedo_rack`
- `utility`
- `mining`
- `salvage`
- `tractor`
- `shield`
- `engine`
- `maneuver_thruster`
- `cargo`
- `boarding`
- `scanner`
- `countermeasure`
- `docking`
- `cosmetic`

## Rules

- Equipment size must be less than or equal to hardpoint size.
- Utility hardpoints must not allow normal guns, missiles, or torpedoes.
- Missile and torpedo racks must not allow normal guns.
- Mining and salvage hardpoints must not allow combat guns.
- Boss and capital frames may use larger sizes, but still stay inside `1..10`.
